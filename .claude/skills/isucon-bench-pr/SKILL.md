# PR の計測と結果の投稿

判定と投稿は `measure.sh` が行う。この skill を実行する担当は、コマンドを実行して結果を報告するだけで、自分でスコアを判定しない。

## 任せ方

Agent ツールで `model: haiku` を指定し、PR の番号と順番、この skill を読むことを伝える。ユーザーの指示がなければ始めない。

## 計測する

ユーザーが指定した順番のまま、バックグラウンドで実行する。1件につき数分かかり、ツールの制限時間を超えるため。

```bash
bash provisioning/bench-bot/measure.sh queue 37 41 36
```

PR ごとに次のように投稿される。

| 判定 | 条件 | 投稿先 |
|---|---|---|
| 改善 | FAIL がなく、中央値が main より3%以上伸びた | PR の本文の「計測結果」 |
| 改善せず | FAIL はないが、3%に届かない | PR のコメント |
| FAIL | 最新の走行が通らなかった | PR のコメント |

計測が終わった PR は `queue` が自動で投稿するので、`report` は実行しない。投稿に失敗したときだけ `measure.sh report <番号>` を実行する。

## 割り込みがあるとき

チームメイトが `flow.sh` を実行すると、自動で次のようになる。操作はいらない。

1. `flow.sh` は、今の PR の走行が終わるのを待ってから始まる
2. `queue` は `flow.sh` の実行中と、終わってから1分の間は待つ
3. 1分たつと `queue` は自動で再開する

`flow.sh` を通さず手元の変更をデプロイした場合も、ビルドから1分の間は待つ。

自動では止まらないのは、手元の変更がないコードの直接のデプロイと、ポータルからの実行、1分より長い作業。そう言われたら、すぐに次を実行する。

```bash
bash provisioning/bench-bot/measure.sh pause "<理由>"
```

今の走行は止めない。終わるまで待ってから戻るので、**戻ってから**チームメイトに伝える。動いている `queue` は止めなくてよく、再開を待ち続ける。チームメイトが自分で `pause` を実行してもよい。

終わったら再開する。

```bash
bash provisioning/bench-bot/measure.sh resume
```

## 止まったとき

`queue` が0以外で終わったら、**同じコマンドを再実行せず、回避もせず**、次をそのまま報告して指示を待つ。

- エラーの全文
- `未計測:` に書かれた PR の番号

## してはいけないこと

- PR のマージ、クローズ (`adopt`、`gh pr merge`、`gh pr close`)
- `--allow-index-drift` の指定、`unlock`、`DROP INDEX`。指示なしでの `baseline`
- 計測の順番の変更、`flow.sh` や `deploy.sh` の直接の実行
- プロセスを kill して計測を止めること。ベンチの要求は取り消せず、ロックも残りうる
- ルーター IP の 443/8080 への接続

## 報告すること

`measure.sh show` の結果と、PR ごとの判定、Job 番号、差分、未計測の PR。分析や採否の提案はしない。
